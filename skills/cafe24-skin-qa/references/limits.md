# 한계·미확인

1. 전용 린터는 '못 찾음'이지 '없음 증명'이 아니다. registry(module 89·변수 194·modifier 13)는 개인 비공식 저장소 파생이며 스스로 "전체 목록 아님, 미등록≠오류"라 밝힌다 → 미등록 module·변수는 WARN, 미등록 modifier만 FAIL(공식 13종 기준).
2. `static_diff.mjs`는 module·`{$변수}`·`@import`/`@js`만 비교한다. `@layout`·`@css` 원문 문법은 공식 확인 못 해 파싱하지 않는다. 변수가 module 안에서만 동작하는 범위 규칙(scope), CSS·JS 내용, 태그 닫힘·중복 id는 검사하지 않는다(4단계 html-validate 담당).
3. `render_check.mjs`의 xans 판정은 공개 페이지에서 관찰한 `xans-{그룹}-{모듈}` 클래스 형식 기준이며 공식 명문 규칙은 아니다. 원본 렌더 기준(`--baseline`)이 없으면 누락 검사는 동작하지 않는다.
4. 렌더 검사는 로그인 없이 도달하는 페이지만 본다. 로그인 후 화면, 주문서, 회원 전용 화면은 사람 로그인이 필요하며 자동 검사 범위 밖(MANUAL).
5. 외부 도메인(추적·분석 등)의 4xx/5xx·요청 실패는 WARN으로만 센다. 필요하면 `--ignore`로 알려진 잡음을 제외하되 사유를 리포트에 적는다.
6. Playwright WebKit은 실제 iOS Safari와 다르다. 영상 자동재생·AR·스크롤 최종 확인은 11단계 실기기.
7. html-validate의 카페24 소스 호환성, 시각 회귀 안정성은 문서 기반 추론이며 실행 검증 전이다.
8. 시험은 공개 샘플 페이지와 로컬 픽스처로만 했다. 코셋·마지 복제 스킨에는 아직 실행하지 않았다.
9. 개발자센터·서포트 문서 다수가 날짜 미표기이고 문서 간 수치가 상충한다(복사본 개수, 웹FTP 한도). 현재 관리자 화면과 대조하지 않았다.
