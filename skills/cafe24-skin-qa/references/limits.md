# 한계·미확인

1. 전용 린터는 '못 찾음'이지 '없음 증명'이 아니다. registry(module 89·변수 194·modifier 13)는 개인 비공식 저장소 파생이며 스스로 "전체 목록 아님, 미등록≠오류"라 밝힌다 → 미등록 module·변수는 WARN, 미등록 modifier만 FAIL(공식 13종 기준).
2. `static_diff.mjs`는 module·`{$변수}`·`@import`/`@js`만 비교한다. `@layout`·`@css` 원문 문법은 공식 확인 못 해 파싱하지 않는다. 변수가 module 안에서만 동작하는 범위 규칙(scope), CSS·JS 내용, 태그 닫힘·중복 id는 검사하지 않는다(4단계 html-validate 담당).
3. `render_check.mjs`의 xans 판정은 공개 페이지에서 관찰한 `xans-{그룹}-{모듈}` 클래스 형식 기준이며 공식 명문 규칙은 아니다. 원본 렌더 기준(`--baseline`)이 없으면 누락 검사는 동작하지 않는다.
4. 렌더 검사는 로그인 없이 도달하는 페이지만 본다. 로그인 후 화면, 주문서, 회원 전용 화면은 사람 로그인이 필요하며 자동 검사 범위 밖(MANUAL).
5. 외부 도메인(추적·분석 등)의 4xx/5xx·요청 실패는 WARN으로만 센다. 필요하면 `--ignore`로 알려진 잡음을 제외하되 사유를 리포트에 적는다.
6. Playwright WebKit은 실제 iOS Safari와 다르다. 영상 자동재생·AR·스크롤 최종 확인은 11단계 실기기.
7. html-validate의 카페24 소스 호환성, 시각 회귀 안정성은 문서 기반 추론이며 실행 검증 전이다.
8. 시험은 공개 샘플 페이지와 로컬 픽스처로만 했다. 코셋·마지 복제 스킨에는 아직 실행하지 않았다.
9. 개발자센터·서포트 문서 다수가 날짜 미표기이고 문서 간 수치가 상충한다(복사본 개수, 웹FTP 한도). 현재 관리자 화면과 대조하지 않았다.
10. 단계 4: html-validate는 규칙을 일부 완화해 둔 프로필이며(스타일·권고류 off), 카페24 기본 모듈의 위반(예: 구형 doctype, script type)은 기준선에 사람이 판정해 등록해야 한다. 소스 직접 검사는 `{$..}`를 'x'로 치환하는 전처리라 속성 이름 자리의 치환변수 등 일부 구조는 정확하지 않다.
11. 단계 5: `isMobile` 에뮬을 쓰지 않아 모바일은 viewport 폭+터치만 재현한다(실제 폰의 자동 축소 동작과 다를 수 있음). 햄버거·팝업 열기/닫기는 `--open` 한 개 셀렉터 클릭만 지원하고 상세 동작은 단계 6 flows로 작성해야 한다. WebKit·Firefox는 공개 페이지에서 로딩 타임아웃이 간헐적으로 났다(사이트·네트워크 영향).
12. 단계 6: 셀렉터는 스킨마다 달라 템플릿(`cafe24-default.template.json`)을 복제 스킨에 맞게 고쳐야 한다. 옵션 선택·장바구니 담기·바로구매는 쓰기성 요청을 동반할 수 있어 기본 차단되며, 허용 여부는 사람이 `allowedWrites`로 판단한다(미시험).
13. 단계 7: headless 크로미움은 H.264를 재생하지 못할 수 있어 `video-not-playing`은 WARN이다. 3D·USDZ는 로컬 픽스처 MIME만 시험했고 카페24 호스팅·업로드 동작은 단계 1 미확인. 모션은 `document.getAnimations()`로 CSS/WAAPI만 보며 JS 라이브러리(GSAP 등) 모션은 놓칠 수 있다.
14. 단계 8: Lighthouse는 서드파티 영향으로 변동이 크다. 공개 샘플은 `--runs 1`만 실행했고 기준선 비교 FAIL은 로컬 픽스처로만 재현했다.
15. 단계 9: 설계안의 Playwright `toHaveScreenshot` 대신 Playwright 스크린샷 + pixelmatch로 직접 비교한다(테스트 러너 없이 단계 스크립트와 같은 구조로 돌리기 위해). 맥북 단일 환경·같은 뷰포트 한정.
16. 단계 10: 로그인·주문·마이쇼핑 경로는 의도적으로 건너뛴다. `--recurse`는 크롤 범위가 커질 수 있다.
17. 단계 11(실기기)은 스크립트가 없다. iOS 시뮬레이터 MCP 또는 사람이 확인하고 `--manual11`로 기록한다.
18. 통합 실행기 `run_all.mjs`: 기준선 대비 "기존/신규" 구분은 (단계·페이지·뷰포트·규칙·상세 앞 90자, 건수·4자리 이상 숫자 정규화) 키 일치로 판정한다. 서드파티(분석·위젯) 응답이 방문마다 달라 외부 도메인 WARN 은 운영 무변경에도 가끔 신규로 뜰 수 있다(FAIL 판정에는 영향 적음).
19. 단계 6 분석 비콘(GA·카페24 로그·네이버·리뷰 위젯 등) POST 는 차단하되 WARN(`beacon-blocked`). 목록에 없는 POST 는 FAIL 이므로 새 서드파티가 붙으면 `flow_check.mjs` 의 `beacon` 정규식에 사람이 판단해 추가.
20. 성능 기준(Lighthouse mobile 시뮬레이션)은 전송량이 큰 페이지에서 LCP 가 수십 초까지 과장된다. 절대값이 아니라 같은 조건 대비 악화만 본다. 기준선은 맥북·같은 네트워크·같은 runs 에서만 비교.
21. 기준선·브랜드 설정(`baselines/`, `brands/*.json`)은 공개 저장소에서 제외했다(.gitignore). 다른 맥에서 쓰려면 `brands/brand.example.json` 으로 새로 만들고 `--mode baseline` 을 다시 돌려야 한다.
