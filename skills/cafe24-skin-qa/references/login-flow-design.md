# 로그인·장바구니·주문서 점검 단계 설계 (설계만, 미구현·미실행)

## 공개 문서 조사 결과 (2026-11-21, 공개 웹만)
| 질문 | 판정 | 근거 |
|---|---|---|
| 운영몰 PG 테스트 모드·가상 결제로 실주문 없이 결제 시험 | 공식 근거 못 찾음 | 도움말·개발자센터 검색에서 안내 없음 |
| 테스트 주문 표시·통계 제외 기능 | 공식 근거 못 찾음 | 도움말 검색(원문 403, 검색 요약만) |
| 주문서 작성 화면 진입이 주문을 만들지 않는다는 공식 설명 | 공식 근거 못 찾음 | 직접 설명 문서 없음 |
| 카드 주문 취소 | 확인됨 | 관리자에서 취소 처리 후 별도로 PG 전체 취소 2단계(support.cafe24.com/hc/ko/articles/8465972977689, 8466116468249) |
| 주문 삭제 | 중간 확신 | 운영자가 직접 처리, 카페24 대행 없음 |
| 개발·테스트용 몰 | 부분 확인 | 별도 샌드박스 문서는 없고 개발자센터 계정으로 무료 몰 ID를 받아 앱 테스트(developers.cafe24.com/cs/front/faq). 운영 스킨 시험용으로 쓸 수 있는지는 미확인 |
| 크롤링·헤드리스 접속 금지 | 개발자센터 약관엔 직접 조항 없음 | 쇼핑몰 이용약관·robots.txt는 확인 못 함(robots.txt 는 CAPTCHA로 막혀 우회 안 함) |

**결론**: 운영 쓰기 없이 가능하다고 *공식 보증*되는 범위는 없다. 현재 구현 범위(공개 페이지 GET, 장바구니 `/order/basket.html`·로그인 `/member/login.html` 화면 진입, 입력·제출 없음)를 넘는 것은 모두 사람 승인 항목이다. 장바구니 담기는 쓰기(장바구니 레코드 생성)로 보고 운영에서 하지 않는다.

## 허용 범위 (현행)
- GET 화면 진입: 장바구니·로그인·검색. 비회원 주문서 화면 진입은 주문 생성 여부가 문서로 확인되지 않아 **하지 않음**(미확인).
- POST·결제·가입·주문 생성: `flow_check.mjs` 가 차단·FAIL.

## 로그인 화면 점검 단계 설계 (단계 6b, 구현 보류)
목적: 로그인 후에만 보이는 화면(마이쇼핑·주문조회·쿠폰·적립금·위시리스트·회원 전용 가격)의 렌더·콘솔·접근성·반응형 점검.
- 방식: 사람이 만든 **테스트 회원 계정**으로 헤드리스 Playwright 가 로그인 폼에 입력 → `storageState` 저장 → 이후 단계 3·4·5·7 을 `--storage-state` 로 재사용. 로그인 자체는 1회, 비밀번호는 환경변수로만 받고 저장·로그에 남기지 않음.
- 읽기 전용 유지: 로그인 후에도 GET 화면만. 마이쇼핑 수정·탈퇴·배송지 저장·쿠폰 다운로드·장바구니 담기·주문은 `flow_check` 쓰기 차단 규칙 그대로 적용.
- 신규 코드: `render_check` 등에 `--storage-state file` 옵션, 단계 6b 흐름 파일(로그인 → 마이쇼핑 → 주문조회 → 쿠폰 → 위시리스트 → 로그아웃 화면 진입 확인).
- 클론 스킨 미리보기에서 로그인이 되는지(세션이 스킨 미리보기와 분리될 수 있음)는 **미확인**(단계 1 H1).

## 필요한 준비물 (운영 책임자·담당자)
1. 브랜드별 **테스트 회원 계정**(일반 회원, 실명·실결제수단 없음) — ID/비밀번호는 비밀번호 관리자·환경변수로만 전달, 채팅·파일에 적지 않기
2. 테스트 계정 전용 등급·쿠폰·적립금(실제 혜택이 새지 않도록 최소) 설정 여부 결정
3. 테스트 주문을 쓰기까지 허용할지 결정 — 허용 시: 관리자에서 해당 주문 취소·PG 취소·삭제를 담당자가 직접 하는 절차와 소액 상품(비공개 품절 상품 등) 지정. 이 경우도 결제 단계는 사람이 한다
4. 개발자센터 테스트 몰(무료 몰 ID)에 스킨을 올려 시험할지 여부(운영 스킨 시험용 가능 여부는 확인 필요)
5. 스킨 미리보기 URL(복제 스킨, 로그인 필요 여부)
6. 카페24 고객센터 문의: ① 테스트 결제 방법 ② 주문서 화면 진입 시 주문 생성 여부 ③ 자동화 접속 허용 범위
