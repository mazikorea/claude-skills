# 에디토리얼 톤 (실행기 + 자동 배정)

모든 실행은 `scripts/tonectl.py` 한 개로 한다. 마지막 줄 JSON의 `STATUS`만 보고 다음 행동을 정한다. LLM 판단이 필요 없는 단계는 저가 모델·프로그램·Buddy가 그대로 실행한다.

## 요청 → 자동 분류 → 모델 배정 (사용자가 매번 지정하지 않음)

| 요청 유형 | 실행 | 배정 |
|---|---|---|
| 확정 필터 적용 ("이 폴더 브릭 적용") | `tonectl.py apply brick <입력> <출력> --sheet` | **Haiku 서브에이전트** 또는 부모가 Bash 1회. 판단 없음 |
| 레퍼런스 심사 ("이 레퍼런스로 톤 따줘") | `tonectl.py gate <폴더> --against brick` | **Sonnet** (결과 JSON을 사용자 문장으로 요약만) |
| 새 필터 생성 (gate READY 후) | `anchorfit.py` 계열로 생성 → 비교본 | **Opus 부모** 설계 + 사용자 육안 확정 |
| 로직·기준 변경, 표준 문서 QC | 코드 수정 | **Opus xhigh 독립 판정자** (qc.md Deep) |

배정 원칙 정본은 `mazi-efficiency` 스킬. 이 표는 이 업무의 적용본이다.

## STATUS별 행동 (핑퐁 최소화)
- `DONE` → 출력 폴더·비교본 경로만 1회 보고.
- `READY` → 새 필터 생성으로 바로 진행.
- `NOT_READY` → `부족` 항목만 그대로 1회 안내(무엇이 몇 장). 추측으로 진행 금지.
- `NEEDS_USER` → `질문`을 그대로 1회 묻기. 예: 기존 톤과 다른 레퍼런스 → 기존 유지 / 새 필터 분리 / 교체.
- `화질실패`(디테일 일치도 <0.95) → 해당 파일 제외하고 보고.

## 기준선 (설계값, 육안 판정으로 보정 중)
- 레퍼런스 자격: 컬러·인물(분할 ≥3%)·피부가 인물 마스크 안에 있음·흰색/그림자 근거·중복 아님. 흑백·풍경·노을·밀착 인화본 제외.
- 충분조건: 고유 통과 8장 이상, 밝은 무채색 보이는 장 5장 이상, 장끼리 톤 편차 4 이하.
- 톤 비교: 피부·밝은곳·그림자 색 ΔE 각각의 최대값 ≤4 = 같은 톤.
- 톤은 장면 평균이 아니라 기준점(피부·무채색·그림자)만 맞춘다. 장면 평균 매칭은 노을·회색벽을 따라가는 실패가 확인됨(2026-11-14).

## 확정 상태
- `filters/brick.json` = MAZI 01 Brick 확정(2026-11-14, 사용자 육안 선택. 기준점 재적합본보다 기존본이 나음).
- `archive/pampa_v7.json` = 보류(저장 가치 낮음, 사용자 판단).
- `refsets/<필터>/` = 톤 비교 기준 레퍼런스(로컬 전용, 저작권상 저장소 제외). Brick은 고유 5장으로 충분조건 미달 → 추가 시 `gate --against brick`.
- 첫 실행 전 `scripts/seg`가 없으면: `swiftc -O scripts/seg.swift -o scripts/seg` (macOS Vision 인물 분할, 픽셀 생성 없음).
