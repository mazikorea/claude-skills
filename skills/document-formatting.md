# Document Formatting

## 1. 적용 범위와 목표

보고서, 엑셀, 스프레드시트, PPT, 워드 등 문서 생성·수정 시 적용한다.
목표는 독자가 핵심과 세부 내용을 쉽게 구별하고 자연스럽게 읽는 것이다.
사용자가 지정한 서식·제출 양식은 우선하며, 아래 값은 별도 지정이 없을 때의 기본값이다.
기존 문서는 요청 범위 안에서 수정하고 내용·수식·입력 규칙을 보존한다.
서식만 개선할 때는 값·수식·행열 순서·시트 구조를 바꾸지 않는다. 기존 필터·드롭다운·보호·메모·링크를 일괄 초기화하지 않는다.

## 2. 공통 원칙

- 흰 바탕과 진한 글씨를 기본으로 한다. **내용의 순서와 간격 → 굵기 → 필요한 배경색** 순서로 구분한다.
- 제목·소제목·열 제목·핵심 결론·중요 수치만 굵게 한다. 본문 전체나 중요하지 않은 행까지 굵게 하지 않는다.
- 모든 텍스트와 헤더는 왼쪽 맞춤. 수량·금액·퍼센트 등 계산하는 숫자만 오른쪽 맞춤한다. 숫자로 된 코드·식별자는 텍스트로 취급한다.
- 셀 병합은 헤더를 포함해 금지한다. 구분은 간격과 굵기로 먼저 해결한다.
- 같은 역할에는 같은 서식을 사용한다. 색·굵기·테두리·글자 크기를 동시에 과하게 쓰지 않는다.
- 비교 자료는 표, 절차는 짧은 목록, 맥락 설명은 짧은 문단으로 쓴다. 단순한 문장을 억지로 표로 만들지 않는다.

## 3. 굵기와 배경색

- 일반 본문은 보통 굵기·배경 채우기 없음으로 둔다. 빈 셀도 흰색을 칠하는 대신 채우기를 제거한다.
- 열 제목은 굵게 표시하고, 구분이 필요할 때만 연한 회색 배경(예: `#F2F4F7`)을 쓴다.
- 핵심 결론·최종 합계·주요 수치는 우선 굵게 표시한다. 추가 구분이 필요한 부분에만 연한 강조색(예: `#EAF2F8`)을 쓴다.
- 확인 필요·오류는 기존 상태란이나 메모로 이유를 표시하고 필요한 경우 해당 셀에 연한 주의색(예: `#FFF4D6`)을 더한다. 원래 값·수식을 상태 문구로 대체하지 않는다. 색만으로 상태나 중요도를 전달하지 않는다.
- 한 셀이 핵심 수치이면서 확인 대상이면 주의 표시를 우선한다. 같은 셀에 강조 효과를 쌓지 않고, 중요도는 굵기·상태는 문구와 필요한 배경색으로 구분한다.
- 중간 소계와 모든 수치에 동일한 강조를 반복하지 않는다. 카테고리별 무지개색, 진한 배경 띠, 기본 줄무늬는 사용하지 않는다.
- 색상은 필요한 역할만 선택한다. 팔레트가 있다고 모든 색을 사용하지 않는다. 본문과 충분히 구별되는 진한 글씨를 유지한다.
- **배경색은 내용을 담은 셀에만 적용한다.** 숫자와 결과가 표시되는 수식도 내용이다. 제목·합계의 배경을 빈 셀까지 길게 연장하지 않는다.
- 빈 행·빈 열·표 사이 간격·표 밖 여백에는 배경색과 테두리를 넣지 않는다. 전체 행·열이나 예상 최대 범위에 일괄 색칠하지 않는다.
- 빈 입력칸은 사용자가 입력할 위치를 알려야 하는 양식에서만 예외로 표시한다. 인접한 항목명이나 안내로 용도를 명시하고 실제 입력 범위로 한정한다.
- 조건부 서식과 표 자동 스타일도 같은 기준을 적용한다. 빈 값이나 빈 문자열을 표시하는 수식에는 배경색이 생기지 않도록 하되, 숫자 `0`은 빈 값으로 취급하지 않는다.

## 4. 스프레드시트 배치와 조작

- 엑셀은 눈금선을 숨긴다: `showGridLines = False`. 대신 모든 셀에 격자 테두리를 넣지 않는다. 헤더 아래나 최종 합계 위처럼 경계가 필요한 곳에만 얇은 선을 사용한다.
- 시작 셀은 표의 용도에 맞춘다. B2 시작이나 A열·1행 여백을 의무로 두지 않으며, 빈 여백을 만들려고 기존 표를 이동하지 않는다.
- **행·열 고정은 기본적으로 하지 않는다.** 한 화면에 들어가는 표와 요약 시트에는 고정을 추가하지 않는다.
- 세로로 긴 표에서 스크롤 후 열 제목을 잃는 경우에만 실제 헤더까지 최소한으로 고정한다. 첫 행이 제목이라고 무조건 고정하지 않는다. 새 표는 제목·설명을 간결하게 배치한다. 기존 표는 고정을 위해 행을 이동·삭제하지 않는다.
- 가로로 넓은 표에서 행 식별이 어려울 때만 필요한 식별 열을 최소한으로 고정한다. 행 고정과 열 고정을 관성적으로 함께 적용하지 않는다.
- 기존 고정은 실제 읽는 데 필요한지 확인한다. 서식 개선 범위에서 불필요한 고정만 해제하고, 데이터만 수정하는 요청에서는 임의로 바꾸지 않는다.
- 열 너비는 내용에 맞추고 긴 설명만 줄바꿈한다. 행 높이는 표시할 줄 수에 맞춘다. 잘림을 피하려고 모든 열을 넓히거나 글씨를 지나치게 줄이지 않는다.
- 같은 지표는 단위·소수 자릿수·날짜 형식을 통일하고 금액·수량에는 필요한 천 단위 구분을 쓴다. 숫자를 텍스트로 바꾸지 말고 표시 형식으로 처리한다. 저장된 값은 반올림하지 않으며 `0`, 누락, 해당 없음은 구별한다. 코드의 앞자리 `0`을 보존하고 퍼센트는 원래 값의 기준을 확인한다.
- 필터는 정렬·조회할 연속된 데이터 표에만 적용한다. 제목·설명·합계·빈 구분 행을 필터 범위에 섞지 않는다.
- 드롭다운은 실제 반복 입력이 필요한 상태·분류 필드에만 사용한다. 읽기용 보고서에는 불필요한 입력 UI를 추가하지 않는다.
- 출처·기준일·단위는 관련 표 가까이에 간결하게 표시한다. 동일한 설명을 매 행 반복하거나 설명용 빈 열을 불필요하게 만들지 않는다.
- 서식 범위는 실제 내용과 의도된 입력칸을 기준으로 정한다. 과거 서식만 남은 마지막 행·열을 데이터 범위로 오인하지 않는다.

## 5. PPT·워드·문서

- 제목과 핵심 결론을 먼저 보이게 하고 근거를 이어서 배치한다. 목적·다음 액션은 문서에 필요한 경우에만 넣는다.
- 제목·소제목·본문의 위계를 크기와 굵기로 구별하고 같은 수준에는 같은 서식을 쓴다.
- 긴 문단 전체를 굵게 하거나 모든 문장을 색상 상자로 감싸지 않는다. 배경색은 핵심 정보의 구분에만 사용한다.
- 표의 빈 여백에는 색을 넣지 않는다. 불필요한 테두리·아이콘·장식·반복 라벨을 줄인다.
- 실제 열람 크기에서 글자 크기·줄바꿈·페이지 넘김·잘림을 확인한다. 한 페이지에 맞추기 위해 글자를 과도하게 축소하지 않는다.

## 6. 저장 후 검증

- 기존 문서는 변경 전 대상 범위의 값·수식·입력 규칙을 확인하고, 저장 후 다시 읽어 보존 여부와 의도한 서식 변경을 대조한다. 서식 정리는 채우기·테두리 등 필요한 속성만 바꾸고 데이터나 셀 전체를 지우지 않는다.
- 스프레드시트는 고정 범위, 병합, 정렬, 눈금선, 채우기와 조건부 서식·표 스타일의 적용 범위를 확인한다. 내용이 없는 마지막 행·열 밖까지 서식이 번지지 않았는지 포함한다.
- 서식을 생성·변경한 산출물은 가능한 렌더 또는 실제 앱 화면으로 제목·본문·합계·긴 텍스트·빈 여백을 확인한다. 다른 레이아웃의 시트·페이지도 확인한다.
- 핵심이 먼저 보이는지, 일반 내용과 강조가 구별되는지, 빈 공간에 불필요한 색이 없는지 확인한다.
- 숫자는 원래 값과 표시값의 단위·퍼센트·자릿수를 대조한다. 색을 제외해도 제목·핵심·확인 사항의 의미를 읽을 수 있어야 한다.
- 재조회만 했다면 시각 검증까지 완료했다고 쓰지 않는다. 렌더가 불가능하면 검증한 범위와 남은 한계를 명시한다.

## 7. Self Checklist

산출물 완료 답변에는 아래 항목의 결과를 짧게 포함한다. 확인한 것만 완료로 표시하고, 해당하지 않는 항목은 해당 없음, 미확인 항목은 미확인으로 구분한다.

- 가독성: 제목·핵심만 선택적으로 강조, 본문과 위계 구별
- 색상: 의미가 있는 최소 범위만 사용, 빈 행·열·여백의 불필요한 채우기 없음
- 배치: 텍스트·헤더 왼쪽 / 계산 숫자 오른쪽, 잘림 없음
- 시트: 병합 없음, 눈금선 숨김, 불필요한 행·열 고정 없음
- 검증: 저장 후 재조회와 시각 검증 여부, 값·수식·입력 규칙 보존, 숫자 표시 정확성
